# 自进化：他是高阶 critic，不是"只能改这几个文件的实习生"

给驱动自进化的 agent，和给要审他的人看的。这里写的不是"允许他做什么"——那种约定挡不住任何人。
写的是三件真的东西：**墙（结构）、账（可查）、人（终点）**，以及他会踩的坑。

## 1. 他在系统里是什么

跟 critic 判一份材料一样，只是阶数高一层：

| | critic | 高阶 critic（自进化负责人） |
|---|---|---|
| 材料 | 工单给它的那份代码 | **这套系统本身**：`workflow/` 那五类文件、会议记录、store、每个成员包里那份原件、journal |
| 判什么 | 这份材料违了哪条规则 | 这套流程哪里不对：哪一步没人做、哪张工单永远不该发、哪条规则量不出来、哪一步白跑 |
| 产出 | `judge` / `objection` 两条材料 | **一份候选设计**（一个目录：三份 api + 工单 + 规则），它的名字是 `Workflow.load(dir).digest()` |
| 谁判他 | —— | 结构（算子表）+ 硬断言 + 账 + **人** |

**他不改正在跑的会**：一张工单发出去，包里带着 `program/`，就钉在发单那一刻的版本上；他改的是
"下一张发什么"。所以"新版本够不到正在跑的会"不是许诺，是打包方式决定的。

## 2. 墙：他造不出新效果（结构，不靠约定）

`interpret` 自己不带实现，一段 viba 能调到的算子**一个都跑不出这张能力表**：

* 一张工单只能调 7 个算子——actor 的 `acknowledge` / `write_code` / `report_done` / `revise_code`，
  assistant 的 `stated_task` / `closing_note`，critic 的 `judge`；
* 一条规则只能调 critic 表里那三个叶子——`code_under_judgment` / `widest_parameters` / `within_limit`；
* 他往 api 文件里**加**一个新算子也没用：声明在 viba 里，实现在表里（Python），加声明只会让那一步
  **永远递延**（工单板上那一格永远不 ✓，发单的那一侧等到超时）。

想量一个新东西（"函数有没有超过 15 行"）＝**改能力表**＝不在这道墙里面。所以自进化的实际内容只有：
**重组既有算子**（怎么排、接在谁后面、判什么、哪张工单在什么条件下该发）。

## 3. 账：他要是绕过设计去动代码或表，会在记录里露出来

这是这一轮补上的东西（之前只有"约定"）：

| 现象 | 在哪看得见 |
|---|---|
| 这一场会跑的是哪份流程、哪一版这一侧的代码 | 会议记录第 2 行：`- 这份流程：<流程摘要>（这一侧的代码：<能力面摘要>）`（`Workflow.digest()` + `host.capability_digest()`） |
| 每张工单发给谁、发出去的那份程序是什么 | `tickets/<工单>/<成员>/program/`（包里带着那一刻的程序，`program/` 的源码就是凭据） |
| 谁答了哪条数据路径下的哪个算子 | 会议记录里每个成员自己写的账：`- <成员>（<角色>）答了 <数据路径> + <算子>`（`member.run_bundle`） |
| 各成员包里那份副本与会议 store 一不一致 | `Meeting.reconcile()` |
| **谁答了不属于自己名下的算子**（写权） | `Meeting.audit()`：按"算子归哪个角色"核对上面那些账 |

`audit()` 是这一轮加的：写权以前只是"构造上成立"，现在是**账上有据可查**。要审他，先看这两个数
（流程摘要、能力面摘要）跟上一场是不是同一个；再看 `audit()` 有没有话说。

## 4. 人：终点

* **能力表的增删**（新算子、新叶子、新实现）＝ 人签字，系统只负责把"谁动了什么"摆到人面前；
* **ADT**（`MEETING_ADT.md`）＝ 类型的规格，不归自进化；
* 他交出候选设计，人（或一个独立的评审流程）决定并入不并入。

## 5. 防不住的那部分，说清楚

**他要是能写仓库里的文件，他就能改代码、改表、伪造账——任何写在文档里的"禁止"都挡不住。**
真正的边界只能由运行环境给：

1. 只给他 `workflow/` 的写权，仓库其余部分对他**只读**（或者他在另一个检出里改，由人/一个提交流程
   把候选并进来）；
2. 跑会议的进程从一份**受信的检出**启动；
3. 于是：**能不能拦住是权限的事，能不能看出来是这里的事**——摘要变了、账目对不上、副本不一致，
   这三样会留在会议记录里。

还缺的（别当成有了）：没有一条"提案"的数据路径/工单（他是在仓库里改，不是通过会议交提案），
没有一个自动的"评审 + 并入"流程，能力面那张"算子 + 谁实现"的清单还不是一个可以直接签字的文件
（现在是三份 api 文件 + 摘要）。

## 6. 他怎么判一份候选（三层，从便宜到贵）

```bash
.venv/bin/python -m pytest tests/test_ticket_centered.py -q   # ① 设计的规矩 + 五张工单真跑一遍（写代码那步脚本化）
.venv/bin/python -m pytest tests -q                           # ② 别把产品弄坏（2 个 tmux 用例缺 conda 环境，本来就红）
.venv/bin/python e2e_ticket_meeting.py --keep                 # ③ 真会：真 agent、真 tmux、真 HTTP（花钱、几分钟）
```

①是硬门：它按设计的规矩断言（下面第 7 节），并且用真的解释器、真的 store、真的规则、真的成员进程
把五张工单走完。③跑完会留在页面上（默认 `--finish leave`），会话头部「工单 n/5」按钮点开是同一份东西。

## 7. 设计的规矩（测试里是硬断言，不是建议）

* 五类文件：三份角色 api + `tickets/*.viba` + `rules/*.viba`；一张工单至少 import 它要调的那些 api；
* 一张工单里每一步只写**调用**（不重复定义类型）；有 `__ret__`；
* 调到的算子必须在它 import 的那份 api 里；
* **数据路径都相对案子**：设计文件里不许出现带 `/` 的路径，也不许出现案子名；
* 规则是程序：`environ` 进、bool 出，有自己的 `__ret__`。

## 8. 他会踩的坑（都付过代价）

1. **viba 只跑 `__ret__` 拉得着的东西。** 几步要接成链（`$after …` / `$code …`），否则那一步
   **永远不发生**——`write_a_draft` 里"回一句知道了"就这么丢过一次。
2. **两步不能落在同一条 (数据路径, 算子) 上**：第二条会**回放**第一条的答案，不重跑。区分靠
   `$env (environ.sub_env << "…")` 换个名字（现在每步一个：`greeted`、`drafted`、`judged`…）。
3. **并集在实参/字段位置要加括号**：`<- $x (mc.A | nil)`；不加就漏到顶层（`MEETING_ADT.md` 自己犯过；
   viba 的结合性是 `**` > `*` > `|`）。
4. **"该发哪一张"** = 要读的都有答案 ∧ 自己的答案一个都还没有 → 设计必须是 DAG；一张工单不能把自己
   已经答过的路径再答一遍（那样它永远不该发）。
5. **同刻多张都该发时，次序是文件名字典序**（`workflow.tickets()`，不是流程序）。现在五张同刻只有一张
   该发，所以顺序无所谓；新设计要么保持这个性质，要么把编号编进文件名。
6. **判语**：`objection` 是 critic 的 `judge` 写下的（合格时是空串）。工单指向不存在的 (路径, 算子)，
   成员进程以"那一步还没答"失败——现场在 journal 的 `ticket_ran` 输出、以及工单板上那一格没有 ✓。
7. **actor 的 `write_code` / `revise_code` 真会叫 agent**（花钱、耗时）；判语合格时 `revise_code`
   直接照原样返回、不再叫。
8. **要交哪个文件**：页面那条路是从**人类第一句话点名的文件名**取的（`quicksort.py`）；设计换产物，
   得跟人类那句话对得上，否则发单被拒（409 "没点名要交哪个文件"）。
9. **`is_complete` 还没接**：现在挡住明显写错的是第 6 节那一层测试。

## 9. 现场在哪

```
runs/<会议号>/ticket_centered/meeting_record.md     流程摘要 + 能力面摘要、每张工单、每个人自己的账
runs/<会议号>/ticket_centered/store/                材料：每条数据路径下一条 Prepare（$call / $measured）
runs/<会议号>/ticket_centered/tickets/<工单>/<成员>/ 每个成员那份原件（program/ + store/）——对账靠它们
runs/<会议号>/streams/events.jsonl                  journal：state/ticket_issued、state/ticket_ran
GET /api/meetings/<会议号>/tickets                  页面那块板子（该发哪一张、谁答的、判语、记录）
```
