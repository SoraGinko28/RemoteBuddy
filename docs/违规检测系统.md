# 违规检测：规则是程序，呈证是数据

> **这份文档说的那一层已经不在 viba 里了**：`compliance/` 搬去了仓库 `demo-viba`，这里写的
> `viba.compliance.is_compliant`、`PreparedStorage` 这些名字在新 viba 里都没有了。RemoteBuddy 也不用它了——
> 一次跑统一走 `interpret` / `exec`：一次跑的答复是一个节点（`$ok` 是答下的值，`$err` 是停在哪、为什么停），
> critic 跑一条规则就是 `interpret(规则文件, 环境)`，读它答的那个 `bool`（`tickets/critic.py`）。
> 下面留着的是这一层当初的说法，读的时候按这一点折算。

---

## 1. 要解决什么

给一份数据（一次 meeting 的记录、一段代码、一份文档），判断它有没有违规。三样东西：

- **规则（rule）**：一个可执行的 viba 模块，环境进、`bool` 出。写规则的是**高权限 Agent**，每条规则经**人批准**之后才生效。
- **呈证（witness）**：规则要判的那份数据，本身也是一个 viba 模块：环境进、数据出。写呈证的是**低权限 critic**——它只把事实填进去，不写结论。
- **判定**：把规则跑起来，读它答的那个 `bool`。

一句话的判定式：

```python
from viba.compliance import is_compliant
verdict = is_compliant("rule_distance.viba", environ)   # -> Result[bool]
```

`Ok(True)` 合规，`Ok(False)` 违规。跑不起来、没有 `__impl__`、答的不是 `bool`——都是 `$viba_program_err`：那是**呈证或规则写错了**，不是"数据违规"。某一步这个宿主没实现，是**递延**（`$not_my_duty_exception`）：这次判定没做完，换一个有这个能力的宿主接着跑。这条分界是整件事的地基：**违规是判出来的 `False`，写错是 `$viba_program_err`，缺实现是递延**。

判定是确定性的：同一份规则、同一份呈证、同一份证据，跑多少次都是同一个答案。

---

## 2. 角色分工

```
高权限 Agent ──► 写规则（viba 模块：环境 → bool）
      │          写宿主里那几个测量函数的实现
      ▼
   人批准 ⇒ 规则生效

低权限 critic ──► 写呈证（viba 模块：环境 → 数据）
      │          只填事实：谁、在哪、什么时候
      ▼
   一次判定 = 跑规则 ──► Ok(True) / Ok(False) / $viba_program_err / 递延
```

- **规则与呈证都是程序**，不是"类型 + 填值"。规则想有几个条件、怎么组合，都是写程序的事（`<<` 给参数、定义复用、模块拆开）。
- **critic 不许写值**：需要"量一下"的东西不是它答，是宿主函数答的，而且那份答案会被存档（第 4 节）。
- **高权限的那一侧才碰判定逻辑**：critic 交出的那份数据里只有事实，没有"我认为它违规"。

---

## 3. 规则长什么样

完整例子在 `viba/compliance/demo/`。一条规则（受害人 (0,0)、嫌疑人 (3,4)、12:30，门槛 5）：

```viba
import case_at_1230 as case_at_1230

Point = $x int * $y int
Case = $victim Point * $suspect Point * $at str

measure_distance =
	int
	<- $env Environment
	<- $evidence Environment
	<- $case Case
	<- { how far apart they were: not pure, so the answer is prepared }

distance_ge =
	bool
	<- $env Environment
	<- $d int
	<- $threshold int
	<- { is that distance at least the threshold? }

__decl__ =
    bool
  <- $env Env

args = __get_args__ << __decl__

case_env = $sub_env << args.env << "case_at_1230"  # 这个案子的数据路径
the_case = case_at_1230 << case_env              # 呈证：那一刻的三个事实
distance = measure_distance << $env ($tmp_sub_env << args.env) << $evidence case_env << $case the_case
threshold = 5
__impl__ = distance_ge << $env ($tmp_sub_env << args.env) << $d distance << $threshold threshold
```

几条读法：

- **一步一个定义**，别把调用套进调用里。一次运行里定义只算一次，所以 `the_case` 就是那份数据本身。
- **`<<` 是给参数**：`f << $tag X`。给的实参要**过槽位**（`C <: B`），过不了当场 `$viba_program_err`——这是类型判定现在唯一还在前台干活的地方。
- **每个可执行函数都要 `$env Env`**；普通调用给 `$tmp_sub_env << args.env`（调用没有数据路径，也不该占一个），只有**测量**多收一个参数 `$evidence`，明说这份证据属于哪个案子。
- **`__impl__` 就是判定**：它必须是 `bool`。
- **函数体里的 `{...}` 是说明**，实现来自宿主的 `get_func(module_path, func_name)`；interpret 自己不带任何库函数。

呈证是数据，规则按**地址**读它（`viba.reflect`）：`$victim`、`$suspect`、`$at` 是地址，`$x`/`$y` 再下一层。呈证不必长得像规则：

```viba
__impl__ =
    $victim ($x 0 * $y 0)
  * $suspect ($x 3 * $y 4)
  * $at "12:30"
```

## 4. 不纯的那一步：Prepare

程序里唯一不能保证"跑多少次都一样"的是宿主函数（读时钟、调服务、量一次距离）。它不许自己答个数就算了——那样结果不可回放。它走 `measure`：

```python
def measure_distance(self, env, evidence, case):
    def compute(prepared):
        victim = _point(prepared, "victim")
        suspect = _point(prepared, "suspect")
        return int(round(...))
    return measure(env, "measure_distance", case, compute, evidence=evidence)
```

`measure(environ, name, call, compute, evidence=...)` 做两件事：

1. 读这次调用的 **Prepare**。里面已经有量出来的值 → **直接回放，`compute` 一次不调**；
2. 没有 → 调 `compute(call)`（不纯的那一步），把值写进**本轮 store** 的 Prepare 里，再答它。

**Prepare 是"这一次测量"的存档**：被固定的调用（参数定了、结果位留着声明）与量出来的值，一份**序列化的 viba 数据**（人读得懂，也能解析回数据），路径 `<案子环境>/prepare/<name>.viba`：

```viba
value =
    $call (
        $victim ($x 0 * $y 0)
      * $suspect ($x 3 * $y 4)
      * $at "12:30"
    )
  * $measured 5
```

两条规矩（`viba/compliance/storage.py` 的 `PreparedStorage`）：

- **读：先看本轮 store，再看备份**（`prepare_root_dir`，运行之前就存好的证据）；
- **写：只进本轮 store，永不写备份**。运行不许改证据。

于是"一次准备、多次判定"：第一次跑测量、存档；之后每次跑都回放同一个值，判定可复现。Prepare 里的 `$call` 压过现场写的 `call`——被固定的那次调用才算数，这就是"准备"的含义。

---

## 5. 判定与错误的分界

| 结果 | 意思 | 谁的问题 |
|---|---|---|
| `Ok(True)` | 规则跑完答 `true` | 合规 |
| `Ok(False)` | 规则跑完答 `false` | 违规 |
| `$viba_program_err` | 规则编不过 / 没有 `__impl__` / 答的不是 `bool` / 实参过不了槽位 / 没有 `$env` | **critic 或规则作者**写错了，退回重做 |
| `$underlying_viba_op_failed` | 某个宿主函数的实现自己坏了 | 宿主；答案里带 `$msg` / `$step` / `$reason` |
| `$not_my_duty_exception`（递延） | 这一步不归这个宿主实现 | **谁都不算错**：这次判定没做完，换一个有这个能力的宿主接着跑 |

这一条替代了"先照类型自查、再判定"那套两段式：类型对不上不再是"先擦掉谓词叶子比一遍"，而是**跑的时候当场 `$viba_program_err`**——给的实参要 `C <: B`，参数位置对不上就进不了判定。

**递延为什么重要**：它是"缺实现"，不是"失败"——两者在解释器里就是分开的（`get_func` 返回 `None` 是"不是我的"，抛别的异常是"我这坏了"）。递延里带着 `$step`（哪个 storage 路径下的哪个定义）和 `$call`（这一步拿到的数据，就是一份 Prepare 固定的那份），所以**拿递延就能直接写工单**，不用再跑一遍；收工单的一方答完写回同一地址，原来那次运行重跑即续跑。对 meeting 的含义是：critic 的宿主不必什么都实现，量不了的那一步就递出去，规则一个字不动。

---

## 6. 和 meeting 的接口：宿主是唯一读数据的地方

规则程序本身是纯的：它只会给参数、跑函数、算 `bool`。**读数据全在宿主的 `get_func` 那一侧**：

- 宿主侧的测量函数才去 store 里按地址读呈证（工单那一侧：critic 把那份数据摆在案子的数据路径下，
  规则从那儿读；读数据只发生在这张能力表里）；
- 因此 `$python_code`（或这里的 `{...}` 说明）里**不许出现实现细节**：不认存储布局、不认 harness 对象、不认 Python 记录类型。一个能看见"数据是怎么存的"的规则，就不再是关于这场 meeting 的规则了；
- `Assert` / `Appendix` / `Hint` 留在设计里当**说明载体**（它们的实参是 code block）；viba 的语言配置把它们算作单位元，所以判定时它们的实参被当作说明跳过，不参与比较。

---

## 7. 类型判定现在还在哪里

`is_sub_type` 没有被废掉，只是从"判定内核"退到"参数适配"这一层：

- 给参数时的 `C <: B`（第 3 节）；
- 类型本身的意义：和是"存在一支"，积是"每一支都要"，函数返回协变、参数逆变，`never` 是和的单位、`nil` 是积的单位，`...` 表示"这块不关心"；
- 别名的展开、泛型代实参、函数链的对位与补齐，都是它的事。

违规与否**不再**由 `Witness <: Rule` 表达——那是旧机制。现在规则是一个程序，判定就是把程序跑完。

---

## 8. 可以拿去当测试的定律

1. **可复现**：同一份规则 + 同一份呈证 + 同一份备份，跑多次结果相同；回放的那次 `compute` 一次都不调。
2. **证据只读**：运行不会写备份目录；新测量只落在本轮 store。
3. **准备压过现场**：Prepare 里的 `$call` 与规则里现场写的调用不同时，算的是 Prepare 那次。
4. **答案必须是 bool**：答别的类型 → `$viba_program_err`，不是 `False`。
5. **实参要过槽位**：给一个不是 `B` 居民的实参 → `$viba_program_err`；不是"判 False"。
6. **判定与错误分离**：`Ok(False)` 只能是规则自己答出来的。
7. **单位元与 `...`**：`A * nil ≡ A`、`A | never ≡ A`、`...` 区域随便填不影响结果（在参数适配层验）。

---

## 9. 一句话

> **规则是程序，呈证是数据，判定是跑一次**；不纯的那一步被 `measure` 单独圈出来，存档成 Prepare，只读备份、只写本轮 store；跑出来 `Ok(True)` 合规、`Ok(False)` 违规、`$viba_program_err` 是写错了、递延是这一步还没人实现（换宿主接着跑）。高权限 Agent 定规则、人点头，低权限 critic 只填事实，智能全在前面，后面全是机械活。
